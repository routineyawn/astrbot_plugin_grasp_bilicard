# Grasp-BiliCard（astrbot_plugin_grasp_bilicard）

群里甩一张 B 站卡片，她这一轮真的看得到画面和原话。
不下载到群里、不经过第二个模型总结、不转发。

> 都是同类插件，原本我没想降维打击！
>
> 我只是想让自己看得到 B 站视频。

- **省 token**：一张 9 格宫格约 418 token；同样内容逐帧发 6 张要 3500 多，差九倍。预算还能往下压到 274、212、158，代价是更糊。
- **快**：5 分钟的视频，字幕齐全时下载 + 扫画面 + 拼图约 8 秒；要本机转写约 20 秒。
  这个数字**从插件开始处理算起**，不含消息在 AstrBot 里排队、防抖插件的等待，也不含你发完卡片到真的 @ 它之间的间隔 —— 口径见下方「耗时怎么算」。
- **清楚**：每格 350×194，按画面变化分段、每段挑最清晰的一帧，不是均匀截图。
- **扛得住**：下载被拦就用 B 站官方故事板兜底，照样有几张画面；字幕对不上自动换轨，再不行改转写。
- **管得住**：群聊要 @、每人每天可限额、临时文件按时清、内网地址一律不理。

## 做了什么

QQ 里的 B 站视频分享是一条**卡片消息**，不是视频文件。AstrBot 默认只把它当一个未知消息段，
模型什么也看不到。这个插件补上中间那段：

1. 认出卡片里的 B 站链接（`b23.tv` / `bili2233.cn` / `bilibili.com`），也认直接打出来的 `BV` 号或 `av` 号；
2. 用 `yt-dlp` 把视频下到本机临时目录（宫格模式 480P，逐帧模式 720P）；
3. 按画面变化密度把前 N 秒分成几段（起伏大的自动多分几格，平缓的省成 6 格），每段挑一张最清晰的画面，
   再拼成一张带编号的宫格（默认最多 9 格；也可以切成独立的几张，见 `frame_style`）；
4. 先试视频自带字幕（UP 主上传或 AI 字幕），拿不到再转写（本机 `sherpa-onnx`，或任意 OpenAI 兼容的语音接口）；
5. 顺便带上视频简介（UP 主写在简介里的说明），不想要就关 `include_desc`；
6. 把"说明 + 画面"塞进这一轮的上下文，模型只在这一轮里看到（说明文字可以用 `prompt_template` 换成你自己的）；
7. 视频实在下不下来时还有一路兜底：改用 B 站官方故事板（videoshot）的缩略图，
   不下载视频也能给模型几张画面（比抽帧糊，聊胜于无）；
8. 抽完帧立刻删掉视频文件，整个临时目录 20 分钟后清。

不经过第二个模型总结，不经过转发，不碰任何付费接口（除非你自己配了云转写）。

## 支持哪些链接

| 链接长什么样 | 会怎么处理 |
| --- | --- |
| `bilibili.com/video/BV...` | 正常处理，横屏竖屏都行（竖屏按短边挑清晰度） |
| `b23.tv/xxxx`、`bili2233.cn/xxxx` 短链 | 先解析成 BV 再处理，解析结果按短码缓存，同一条卡片只解析一次 |
| 直接打 `BV1xx...` / `av12345` | 正文里认出来就处理，不需要卡片 |
| `?p=3` 多 P 视频 | 只处理第 3 P，缓存也按 P 分开 |
| 有 UP 主上传字幕的视频 | 优先用自带字幕，省掉转写 |
| 没有对白的纯音乐、空镜 | 照常出画面；转写只出几个字时判定为「没听到内容」，不把「嗯嗯嗯」当台词喂模型 |
| 番剧 / 课程 / 付费内容的 `ep` `ss` 链接 | **不支持下载**（这类链接里没有 BV 号），只能给 B 站官方故事板缩略图 |
| 已删除、私享、限时过期的视频 | 给标题 + 故事板兜底，不会编内容 |

番剧那条是刻意的：付费集有「试看 6 分钟」「只放 30 秒」几种残缺形态，硬接容易把半截内容当成全片，
不如老实给几张官方缩略图。

## 和其他 B 站插件的区别

- **BiliRead / 字幕总结类**：读视频字幕，交给第二个模型总结成一段话。省流量，但没有画面，
  视频没字幕就用不了，而且多一层转述。
- **直链解析类**：只把清晰度、标题、直链发出来给你，不喂模型。
- **本插件**：把画面直接交给正在对话的模型，模型自己看、自己说；视频有声音时还能把话转成文字一起看。
  代价是要下载、要等、按图片张数花钱。

## 这个插件的定位

只做桥：把 QQ 里的 B 站卡片变成这一轮对话能读的画面和文字。

真正看懂视频交给对话模型本身，不在这里再套一层「总结」。社区里出现更好的读视频方式
（更好的抽帧、更准的字幕、以后直接吃视频的模型），换掉这一小段就行，桥不用动。

## 安全与隐私

这个插件要读视频、要带 Cookie 请求 B 站、要把画面和文字交给模型，所以把边界写清楚。

### 离开这台机器的东西

| 去向 | 内容 | 时机 |
| --- | --- | --- |
| `api.bilibili.com`、`www.bilibili.com` | BV 号、cid；配了 Cookie 时带 `SESSDATA` | 每次处理视频 |
| B 站视频 CDN | 只下载，不发数据 | 下载视频 |
| 你自己配置的模型服务商 | 画面宫格、字幕或转写、视频简介 | 每轮交给模型时 |
| 你自己配置的转写接口（`asr_mode=openai`） | 前几分钟的音轨 | 需要转写时 |

除此之外没有别的外发：没有遥测、没有统计上报、不访问第三方域名。Cookie 只发给 `b23.tv`、`bili2233.cn`、`bilibili.com` 及其子域名，`extra_sites` 里加的站点一律不带 Cookie。

### 留在这台机器上的东西

- `SESSDATA` 明文写在插件配置里（`data/config/astrbot_plugin_grasp_bilicard_config.json`），只在本机。不填也能用，代价是部分字幕和某些清晰度拿不到。
- 视频、画面、音轨都是 AstrBot 临时目录里的临时文件，`sweep_minutes` 分钟后清掉。
- 处理条数的计数放在内存里，重启归零。

### 会启动的子进程

`ffmpeg`、`ffprobe`、`yt-dlp`，可选 `sherpa-onnx-offline`。参数用列表传，不开 shell，消息里的原文不会拼进命令行。

### 建议

- 给机器人单独一个 B 站账号，Cookie 万一泄露不牵连主账号。
- 发现安全问题走仓库的「私人漏洞报告」，别开公开 issue —— 细节见 [SECURITY.md](SECURITY.md)。

## 可能出问题的地方

不是免责声明，是把已知的坑先摆出来。

### 视频内容本身不可信

字幕、标题、简介、热评都是**别人写的文本**，会被塞进这一轮上下文。也就是说，任何人只要发一条视频，
就能让这段文字出现在你的模型面前 —— 里面完全可以夹一句「忽略前面的要求」。

插件能做的：热评模板里写明「评论区是别人说的，不一定对，和画面冲突时以画面为准」；画面走图片通道，不进正文。
插件做不到的：替你判断某句话是不是有人在钓鱼。别把这个机器人放进「有人专门喂料」的群里，尤其是它有权动文件、跑命令的时候。

### 文字可能出错

- 字幕是 B 站给的，可能串片、可能语言不对。插件会校验覆盖时长与标题命中率，明显不对就换轨道或转写，但个别情况仍会带进错的字幕。
- 本机转写会听错，尤其是歌、方言、多人抢话。
- 只给画面不给台词时，模型对剧情的判断会偏。

### 拿不到画面的时候

退到官方故事板，再不行只给标题。**这时候不是「看过了」，是「知道有这么个视频」。** 具体哪类链接会这样见「限制与代价」。

### 会被限流

同一个账号短时间内反复处理，B 站会限流甚至让短链 404。`daily_limit` 可以用来给群里设个上限。

### 依赖会过期

`yt-dlp` 对 B 站的支持靠上游跟进，接口一变就可能失效，需要你自己去更新它。插件不联网升级依赖。

### 占资源

`ffmpeg` 抽帧和本机转写都吃 CPU，转写是纯 CPU 单线程。同时最多下载 2 条，多了会排队。

### 花 token

一条视频约 1,300 token（画面约 400，文字约 900），群里刷起来是真金白银。`daily_limit` 与 `subtitle_limit` 都能压。

### 版权与使用边界

只处理使用者主动发来的链接，供个人观看用；不批量抓取，不绕付费墙、会员或 DRM，不托管、不转发视频文件。
视频版权归 B 站与 UP 主，拿它去做什么由使用者负责。

### Cookie 的泄露途径

`SESSDATA` 明文存在插件配置里。会泄露它的场合是：配置被备份到网盘、截图时没遮、把日志发给别人、
或者装了这个机器人的那台机器本身被别人拿到。用一次换一次、只给小号用，代价最小。

### 出了事怎么算

本插件按 MIT 提供，**不承诺适用性**（见 [LICENSE](LICENSE)）。能用、够用、出错会老实说，
但画面糊了、字幕错了、模型把热评当事实、B 站改接口导致不能用了，这些都不构成对作者的索赔理由。

## 安装

1. 把整个 `astrbot_plugin_grasp_bilicard` 目录放进 AstrBot 的 `data/plugins/`，或在插件管理里上传 zip；
2. 依赖：`pip install -r requirements.txt`（`yt-dlp` 下载、`numpy` 算画面变化、`Pillow` 拼宫格、`imageio-ffmpeg` 带一份 ffmpeg）；
3. `ffmpeg` 不用自己装：`imageio-ffmpeg` 会带一份，插件优先用它；想用系统自带的就在配置 `ffmpeg_bin` 里写路径；
4. 在 AstrBot 后台启用插件，按需改配置。

没有 `ffmpeg` 时插件只会给你标题，不会编视频内容。

## 用法

- 私聊直接发一张 B 站卡片，或者直接打 `BV1...` / `av12345`；
- 群里先发卡片，再 @ 机器人问一句（默认设置，10 分钟内有效）；
- 也可以引用一张旧卡片再发一句话，插件会从被引用的消息里找链接。

## 配置

配置页现在分四组：**入口**、**画面**、**文字**、**安全**。

### 入口

| 项 | 默认 | 说明 |
| --- | --- | --- |
| `watch_qq_card` | `true` | 总开关 |
| `prefetch_on_card` | `true` | 卡片一到就开始下载，等下一句 @ 时直接出结果；关掉则每次现场等下载 |
| `require_at_in_group` | `true` | 群里要 @ 才处理 |
| `card_wait_seconds` | `300` | 群里先发卡片、后 @，这张卡片等多久；超过就忘掉。只认同一个人的卡片 |
| `daily_limit` | `0` | 同一个人每天最多处理几条；`0` 不限。群里人多可以填个 10 |
| `extra_sites` | `""` | 额外允许的站点域名，逗号分隔（如 `douyin.com,xiaohongshu.com`）；默认只认 B 站 |

### 画面

| 项 | 默认 | 说明 |
| --- | --- | --- |
| `frame_style` | `board` | `board` 拼成一张宫格（省 token）；`frames` 每格一张独立图（更清楚、贵得多） |
| `board_cells` | `9` | 宫格格数上限：平缓的视频自动降到 6 格，起伏大的用满这个数；还会按像素预算再压一次 |
| `board_budget` | `640000` | 宫格整图像素预算，直接决定 token：640000 约 418，420000 约 274，320000 约 212，250000 约 158，900000 约 569 |
| `scan_fps` | `4` | 扫画面变化用的帧率；4 约 4.8 秒，2 约 2.4 秒，8 约 8.5 秒 |
| `pick_sharp` | `true` | 每段取 3 个候选点挑最清晰的一张，避开转场和运动模糊；关掉只取段中点，更快 |
| `frame_count` | `6` | `frame_style=frames` 时最多截几张画面 |
| `clip_seconds` | `300` | 只处理前 N 秒（默认 5 分钟） |
| `size_limit_mb` | `120` | 下载大小上限，超过只给标题 |

### 文字

| 项 | 默认 | 说明 |
| --- | --- | --- |
| `prefer_subtitles` | `true` | 先试视频自带字幕，拿不到再转写 |
| `subtitle_limit` | `800` | 字幕或转写最多带多少字进上下文，超了截断 |
| `include_desc` | `true` | 带上 UP 主写的视频简介；关掉就只看画面和字幕 |
| `include_tags` | `true` | 带分区和标签，让模型先知道这是哪一区的视频 |
| `comments_max` | `5` | 有字幕时带几条热评；0 = 不带 |
| `comments_max_no_subtitle` | `8` | 没字幕时带几条热评（这时评论是唯一的语义来源） |
| `comments_chars` | `200` | 每条热评最多留几个字 |
| `asr_mode` | `off` | `off` / `local` / `openai` |
| `local_asr_home` | `""` | 本机识别目录（含 `sherpa-onnx-offline.exe`、`model.int8.onnx`、`tokens.txt`） |
| `remote_asr_base` | `https://api.siliconflow.cn/v1` | OpenAI 兼容接口地址 |
| `remote_asr_key` | `""` | 远程转写 Key |
| `remote_asr_model` | `FunAudioLLM/SenseVoiceSmall` | 远程转写模型 |
| `prompt_template` | `""` | 自定义引导语，留空用内置文案。可用 `$title`/`$length`/`$cut`/`$desc`/`$shot`/`$sound` 占位 |

### 安全

| 项 | 默认 | 说明 |
| --- | --- | --- |
| `bili_cookie` | `""` | 可选，见下；只填 `SESSDATA` 的值也行，插件会自己补成 Cookie 头 |
| `ffmpeg_bin` | `""` | 留空自动找 PATH 和 `C:fmpegin` |
| `sweep_minutes` | `20` | 临时文件保留分钟数 |

### 怎么按需要组合

每个都是独立开关，没有一键模式。下面只是几种常见配法，可以自己混着调：

| 想要 | `prefer_subtitles` | `asr_mode` | `pick_sharp` | `board_cells` | `board_budget` | `scan_fps` | 实测 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 默认，平衡 | `true` | `local` | `true` | `9` | `640000` | `4` | 418 token |
| 省 token | `true` | `local` | `false` | `6` | `320000` | `2` | 212 token |
| 更省 | `false` | `off` | `false` | `6` | `250000` | `2` | 158 token，约 11 秒 |
| 最清楚 | `true` | `local` | `true` | `12` | `900000` | `8` | 569 token |

（上表是同一条 7:20 视频的画面部分实测，token 按 `ceil(w/42)*ceil(h/42)` 折算。）

### 关于 B 站 Cookie

不填也能用：匿名访问能拿到 360P/480P，看画面足够。以下情况才需要填：

- 想要 1080P 及以上（大会员视频）；
- 视频被限制成"登录可见"；
- 频繁下载触发了风控。

填法：浏览器登录 B 站 → F12 → 网络 → 任意一个 `bilibili.com` 请求 → 复制 `Cookie` 整串，
粘到 `bili_cookie`。也可以只粘 `SESSDATA` 的值，插件会自己补成 `SESSDATA=...`。
插件不校验、不打印、不上传，只透传给 `yt-dlp`。

## 临时文件

- 位置：`<AstrBot 数据目录>/temp/bili_card/`（Windows 一般是
  `C:\Users\<你>\.astrbot_launcher\instances\<实例>\core\data\temp\bili_card\`）；
- 每条视频一个子目录，抽完帧立刻删掉视频和音频，只留画面；
- 超过 20 分钟的子目录在下次处理时自动清掉；
- 卸载插件后这个目录可以直接删。

## 耗时怎么算

上面那些秒数，计时起点是插件拿到这一轮请求的那一刻，终点是画面和文字都塞进上下文。所以它**不包含**：

- 消息在 AstrBot 里排队的时间，以及防抖类插件（先攒句子再交上来那种）的等待 —— 这段由那些插件决定，不归本插件管；
- 群里从「有人发卡片」到「你 @ 它」之间的间隔 —— 这段时间插件空闲，卡片一到就开始预下载，所以你 @ 下去时通常只剩解码和转写；
- 模型自己生成回答的时间。

波动最大的是**下载段**：同一个视频，网络好时 4.7 秒，碰上不通的 CDN 节点会退到 100 秒以上（已改成 5 秒超时、重试 1 次，失败就用官方故事板兜底）。
机器配置、有没有拿到 B 站自带字幕、装没装别的插件，都会影响体感时间。

## 限制与代价

- 每条视频要等：下载几秒到几十秒，截帧和转写再加几秒到十几秒；
- 只处理前 `clip_seconds` 秒，后面的内容看不到；
- 番剧、课程、付费内容（`ep` / `ss` 链接）不下载，只有官方故事板缩略图——这类链接里没有 BV 号；
- 下载失败时会说明是哪一类（视频被删、会员限定、超过大小上限、网络超时），并尽量用 B 站官方故事板兜底给几张缩略图；
  故事板是 160×90 的小图，比抽帧糊得多，偶尔还会带黑帧；连故事板都拿不到才只给标题，不会编内容；
- 字幕不是每条都有：B 站的字幕接口要登录（`bili_cookie`），而且它本身不太稳定——
  同一个视频有时给正常字幕、有时给空、偶尔还会把别的视频的字幕递过来；插件会换轨重试、检查中文占比，
  再用「覆盖时长」和「标题词」两道校验，对不上就整份丢掉走转写，不会拿错字幕去骗模型；
- 画面按图计费：`frame_style=board` 时 9 格宫格约 400 token 量级，`frames` 时 6 张 720p 约 3500 token 量级——差价接近九倍，想看细节才切 `frames`；
- 群聊里如果先发卡片、后发 @，中间那轮回复可能看不到画面，等 @ 那轮就有了；
  只有**同一个人**在 `card_wait_seconds` 内接着 @ 才算数，别人接着 @ 不会用到你的卡片；
- 群友也能触发下载和模型调用（一次约 1700 token）：想控成本就开 `daily_limit`，或者群里保持 `require_at_in_group` 开着；
- `extra_sites` 只收公网域名，本机、内网地址一律忽略，不会被一条消息引着去请求自家服务；
- `bili_cookie` 和 `remote_asr_key` 都以明文存在本机配置文件里，能读这台电脑就能读到；只填 `SESSDATA` 的值就好，过段时间在 B 站退出重登一次，旧值就作废。

## 模型只描述画面怎么办

插件在说明里已经写清楚了：画面是按时间抽的样、请连起来理解整个视频在讲什么、回的时候用你自己的话说内容、别一格一格描述画面里有什么。

但模型不一定听。如果人格卡把机器人设得很强势（比如"看到什么就说什么"），她可能还是只报"第 8 格有个蓝发女孩"。这时最有效的不是在插件里加更多提示，而是在**人格卡 / 系统提示**里补一句：

> 看完视频，先说这段视频讲了什么、讲了哪几件事，不要逐格描述画面里有什么。

插件这边不硬性规定输出格式——那是人格的事，插件只负责把内容送到模型眼前。
